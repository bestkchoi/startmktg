# Start Marketing – 개발 히스토리 (2025-11-21 기준)

## 1. 전체 개요
- Start Marketing은 **캠페인 UTM 자동 생성(Start Campaign)**, **단일 URL UTM 생성/검증(UTM Checker)**, **Tower Admin(회사/권한/플랫폼 설정)**을 중심으로 하는 마케팅 운영 플랫폼이다.
- 백엔드는 Supabase(PostgreSQL)를 사용하고, 프론트는 Next.js App Router 및 Tailwind UI로 구성되어 있다.

---

## 2. 회원 & 워크스페이스 시스템
- **마이그레이션:** `20250111_create_user_system.sql`
- **핵심 내용:**
  - `public.users` 테이블 정의/확장 (이메일, 이름, `avatar_url`, `updated_at` 컬럼 등).
  - 회사 이메일 관리용 `user_company_emails` 테이블 생성 (`workspace_id`, `company_email`, `verified`, `verification_token` 등).
  - `update_updated_at_column()` 트리거 함수로 `updated_at` 자동 업데이트.
  - RLS 정책:
    - 사용자는 **자신의 user row**만 조회/수정 가능.
    - `user_company_emails` 역시 `auth.uid() = user_id` 인 레코드만 조회/생성/수정 가능.
  - 헬퍼 함수:
    - `is_gmail_email(email text)` : Gmail 여부 판별.
    - `generate_verification_token()` : 32바이트 랜덤 토큰 생성.

## 3. Start Campaign 시스템

### 3.1 PRD 기반 기능 개요
- **문서:** `PRD_StartCampaign_v1.0.md`, `PRD_StartCampaign_v1.1.md`
- **목표:** 캠페인 단위로 여러 매체 채널을 묶고, 각 채널의 **UTM 파라미터를 템플릿 기반으로 자동 생성**하여 일관된 추적 URL을 만드는 서비스.
- **핵심 가치:**
  - 캠페인 생성부터 채널별 추적 URL 생성까지 3분 이내 완료.
  - 매체별 표준 템플릿으로 인한 UTM 오류율 감소 및 네이밍 규칙 통일.

### 3.2 주요 기능 (요약)
- 캠페인 관리
  - 캠페인 생성/조회/수정/삭제 (이름, 기간).
  - 캠페인 상세 페이지에서 매체 리스트 및 URL 미리보기.
- 매체(채널) 관리
  - Meta, Google, Kakao, CRM(SMS/LMS/Kakao), TikTok, 기타 등 매체 타입 추가.
  - 채널별 랜딩 URL, 최종 URL, 생성일, 삭제 기능.
- UTM 생성
  - 매체 선택 + 랜딩 URL 입력 시 UTM 자동 생성.
  - 템플릿 변수(`{{campaign_name}}`, `{{channel_type}}`, …) 기반 UTM 규칙.
  - 커스텀 content/term 입력 시 템플릿 값 덮어쓰기.
- 템플릿 관리
  - `utm_templates` 테이블 기반 매체별 UTM 패턴 저장.
  - v1.0에서는 기본 규칙(템플릿 없을 때 `channel_type`, `campaign_name` 기반 생성) 사용.

### 3.3 DB 마이그레이션
- **`20250111_create_campaign_system.sql`**
  - `campaigns` 테이블: `id`, `campaign_name`, `start_date`, `end_date`, `user_id` 등 기본 구조.
  - `campaign_channels` 테이블: 캠페인별 채널, UTM 파라미터, 최종 URL 저장.
  - `utm_templates` 테이블: 매체별 UTM 패턴 저장, `channel_type` UNIQUE 인덱스.
  - `update_campaign_updated_at()` 트리거로 각 테이블 `updated_at` 자동 업데이트.
  - RLS:
    - 사용자는 **자신이 생성한 캠페인/채널**만 조회·삽입·수정·삭제 가능.
- **`20250115_create_start_campaign_system.sql`**
  - Start Campaign PRD v1.1 요구사항에 맞춰 `campaigns`를 재설계.
  - 신규 컬럼:
    - `campaign_id` (PK), `raw_name`, `normalized_name`, `final_campaign_name`.
    - `brand_id` (현재는 `user_id`와 동일한 의미로 사용), `creator_user_id`.
  - 제약조건:
    - 동일 `brand_id` 내 `final_campaign_name` 유니크.
    - `end_date`는 `start_date` 이후 또는 NULL 허용.
    - `normalized_name`은 소문자 영어로 시작.
  - 인덱스: `brand_id + created_at`, `creator_user_id + created_at`, `final_campaign_name`.
  - RLS: `creator_user_id = auth.uid()` 인 레코드만 접근 가능.

### 3.4 프론트/라우팅 구현
- Next.js App Router 경로:
  - `/[locale]/dashboard`, `/[locale]/campaigns`, `/[locale]/campaigns/new`, `/[locale]/campaigns/[id]`, `/[locale]/campaigns/[id]/channels/new` 등.
- 주요 UX:
  - 3단계 플로우: **캠페인 생성 → 매체 선택 → UTM 생성 및 URL 복사**.
  - 반응형 UI, 입력 검증, 토스트(복사 완료) 등이 구현됨.

## 4. UTM Checker 시스템

### 4.1 PRD 개요
- **문서:** `prd_utm_checker_v_1.md`
- **목표:** 단일 랜딩 URL을 입력하면 **GA4 표준 UTM 파라미터**를 자동으로 생성·검증하고, 최종 추적 URL을 만들어주는 도구.
- **타깃 사용자:** 퍼포먼스 마케터, 광고운영 담당자, CRM 메시지 담당자.

### 4.2 주요 기능
- 랜딩페이지 URL 입력 및 실시간 유효성 검증.
- GA4 표준 UTM 자동 생성:
  - `utm_source`, `utm_medium`, `utm_campaign` (필수)
  - `utm_content`, `utm_term`, `utm_source_platform`, `utm_id` (선택/고급).
- 매체별 커스텀 파라미터 감지:
  - Meta: `fbclid`
  - Google: `gclid`
  - Naver: `n_media`, `n_query`, `n_ad_group`, `n_campaign`, `n_rank`
  - Kakao: `k_campaign`, `k_creative`, `k_medium`, `k_keyword`
  - Criteo: `criteo_p`, `criteo_c`, `criteo_r`
- 감지된 파라미터를 UI 배지로 표준화된 문구와 함께 노출 (GA4 기본/선택, 매체별 색상 배지).
- 최종 URL 미리보기 및 클립보드 복사 기능.
- Supabase에 로그 저장 + 최근 10건 이력 조회 API.

### 4.3 데이터 및 API 설계
- DB 스키마: `fact_utm_log`
  - `base_url`, GA4 UTM 컬럼, `meta_params(jsonb)`, `final_url`.
- API:
  - `POST /api/utm-checker` : 입력 URL 분석, UTM 생성, 로그 저장, 최종 URL 반환.
  - `GET /api/utm-checker/:id` : 특정 기록 조회.
  - `GET /api/utm-checker` : 최근 10건 조회.

### 4.4 프론트 구현 개요
- 경로: `/[locale]/utmchecker`
- 주요 컴포넌트:
  - `form-card`: URL 및 UTM 입력/검증 폼.
  - `parser-card`: 기존 URL에서 매체 파라미터 분석.
  - `results-card`: 최종 URL 및 파라미터 목록 표시, 복사 버튼.
  - `history-card`: 로컬/서버 이력 표시.
- 유틸/훅:
  - `buildUtmUrl`, `detectPlatformParams`, `sanitizeUtmParams`, `validateBaseUrl`.
  - `use-local-history` 훅으로 최근 사용 이력 로컬 저장.

## 5. Tower Admin 시스템

### 5.1 개요
- **문서:** `PRD_Tower_v1.0.md`, `TOWER_DATABASE_SETUP.md`, `TOWER_IMPLEMENTATION.md` 등.
- **목표:** 회사(Company) 단위로 사용자, 권한(Role Tree), 플랫폼 데이터(랜딩 채널/매체/목표/UTM Rule), 모니터링 로그를 통합 관리하는 어드민 시스템.

### 5.2 DB 마이그레이션 (요약)
- **파일:** `20250116_create_tower_system.sql`
- users 확장:
  - `google_sub_id`, `photo_url`, `is_tower_operator` 컬럼 추가 및 인덱스.
- 회사 및 권한:
  - `companies` : 회사 기본 정보(국가, 사업자번호, 도메인 등), `created_by`.
  - `company_roles` : 회사별 역할 계층 구조(level 1~5, parent_role_id), `permissions(jsonb)`.
  - `company_memberships` : 사용자–회사–역할 매핑, 상태(active/suspended).
- 초대/접근 요청:
  - `invitations` : 이메일 초대, role, region, token, 만료일, 상태 관리.
  - `access_requests` : 사용자가 회사 접근 권한을 요청하는 레코드.
- 플랫폼 데이터:
  - `landing_channels` : 회사별 랜딩 채널 이름/URL.
  - `media` : 회사별 광고 매체(Meta/Google/TikTok 등).
  - `objectives` : 매체별 캠페인 목표(traffic/conversions 등).
  - `utm_rules` : 회사별 UTM 규칙(층위 규칙 포함).
  - `custom_rules` : Pro 전용 커스텀 규칙(조건 기반).
- 모니터링 로그:
  - `logs_campaign` : UTM/캠페인 관련 액션 로그.
  - `logs_media` : 매체/랜딩채널/룰 변경 이력.
  - `logs_utm_generator` : Tower 환경에서의 UTM 생성 로그.
- 공통:
  - 대부분의 테이블에 `created_at`, `updated_at` 및 적절한 인덱스를 추가.

### 5.3 Tower 프론트/서버 구현
- Next.js 경로:
  - `/[locale]/tower` : Tower 대시보드.
  - `/[locale]/tower/companies` : 회사 리스트.
  - `/[locale]/tower/companies/create` : 회사 생성 플로우.
  - `/[locale]/tower/companies/[companyId]` : 회사 상세/프로필/멤버/역할/로그 뷰.
- 서버/라이브러리:
  - `src/server/tower/*` : 회사 생성/조회 서버 액션.
  - `src/lib/tower/*` : company, role, membership, invitation, logs 등 비즈니스 로직 모듈화.
  - `src/app/actions/tower/*` : Tower 관련 서버 액션 핸들러.
- UX:
  - 회사 생성 시 사업자번호 검증(`validateBusinessNumber`).
  - 멤버/역할/로그 탭으로 구조화된 상세 화면.
